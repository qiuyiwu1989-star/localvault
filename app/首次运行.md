# 首次运行：装到别的电脑上，要经过哪几步

> 采集时间 **2026-10-02**，本机 **macOS 26.6.2**（`sw_vers`）。
> 这份文档只写**实测过**的东西；没验过的地方单独列在最后一节。
> **凡是这里没写的"应该能行"，都不要当成事实。**

---

## 先把那句话回答掉：「装完就能用吗」

**不能。** 装完还需要你做两件手动的事，一件都省不掉：

| # | 卡在哪 | 为什么 |
|---|---|---|
| 1 | **首次打开会被 Gatekeeper 拦** | 这个包是 **adhoc 签名**、**未公证**。`codesign -dvv` 输出 `Signature=adhoc`、`TeamIdentifier=not set`；本机 `security find-identity -v -p codesigning` = `0 valid identities`（一张 Apple 开发者证书都没有）。`spctl -a -vvv --type execute` 的实测结果是 **rejected** |
| 2 | **App 需要索引才打得开** | 它读 `~/.localvault/vault.db`，那个库由命令行工具建。没有库时 App 不会白屏，会显示「还没有可读的索引」，并给出一条**在这台机器上真能跑**的命令（PATH 上有 `localvault` 就给短命令；没有、但找得到仓库里的 CLI 源码就给 `node …/cli.js …` 并说清缺不缺 Node；两样都没有就**不编命令**，直接指到这份文档的 1.2 节） |

所以完整顺序永远是：**先建索引 → 再装 App → 手动放行一次。**

| 前提 | 要求 | 不满足会怎样 |
|---|---|---|
| 芯片 | **Apple Silicon（arm64）** | 这个包是 `Mach-O 64-bit executable arm64`（`lipo -info` 实测），**Intel Mac 上根本跑不起来** |
| 系统 | **macOS 14.0+** | `LSMinimumSystemVersion` = 14.0；用了 Swift Charts 的 `SectorMark`，13 上会崩 |
| 索引 | `~/.localvault/vault.db` | App 显示「还没有可读的索引」 |
| Node（仅建索引时需要） | **>= 22.5** | CLI 用 Node 内置的 `node:sqlite`，低版本 CLI 会直接给出提示并退出（exit 2） |

---

## 一、先建索引（在目标机器上做）

App 是**只读的图形界面**，索引不是它建的。索引由 CLI 建。

### 1.1 `npx localvault` 现在**还不行**（2026-10-02 实测）

项目 README 里写的是：

```sh
npx localvault init && npx localvault index
```

**这两条在今天的机器上会失败**，因为 `localvault` 这个包**还没有发布到 npm**。实测：

```sh
$ curl -s -o /dev/null -w '%{http_code}\n' https://registry.npmjs.org/localvault
404
$ curl -s -o /dev/null -w '%{http_code}\n' https://registry.npmmirror.com/localvault
404
$ curl -s "https://registry.npmjs.org/-/v1/search?text=localvault&size=20" | grep -c '"name":"localvault"'
0
```

```
（0 = npm 搜索里没有这个包名）
```

所以现在只有下面两条路。**包一旦发布到 npm，上面那两条命令才成立**，这一段就可以删掉。

### 1.2 路 A：把 CLI 目录拷过去（推荐，今天就能走通）

CLI **零第三方依赖**，不需要 `npm install`，整个目录拷过去就能跑：

```sh
# 0. 目标机器上先确认 Node 版本（>= 22.5）
node -v

# 1. 把源机器上的 mcp-server/ 整个目录拷到目标机器（AirDrop / U 盘 / scp 都行）

# 2. 认一下这台机器要索引哪些目录（一次性）
node /path/to/mcp-server/cli.js init

# 3. 建索引（首次几秒到几分钟；之后是增量的）
node /path/to/mcp-server/cli.js index

# 4. 可选：自检
node /path/to/mcp-server/cli.js doctor
```

`init` 零配置时**只探测系统标准目录**（`~/Desktop`、`~/Downloads`），不会默认索引整个主目录。
指定自己的目录：

```sh
node /path/to/mcp-server/cli.js init ~/Documents/项目:工作区 ~/Desktop:桌面
```

> 目标机器上**没有 Node** 怎么办？那就只能走路 B，或先装 Node。
> 本机（这台 Mac）的 `node` 只存在于 DSH 自带的运行时里，用户的 shell 里 `node not found` ——
> **不能假设目标机器有 Node。**

### 1.3 路 B：把索引库直接拷过去

```sh
# 目标机器
mkdir -p ~/.localvault
# 源机器 → 目标机器
#   ~/.localvault/vault.db   （索引本体，可重建）
#   ~/.localvault/config.json（可选）
#   ~/.localvault/claims.db   （可选，见下）
```

三条诚实边界：

- **索引里存的是源机器的路径。** 目标机器上这些路径大多不存在。App 打开的是索引里的**书目**，不是磁盘上的文件 —— 所以它能显示文件列表和正文，但「在 Finder 里显示」会落空，检索结果也只是源机器那一刻的快照。**两台机器目录结构不同的时候，拷贝索引的价值很有限。**
- `config.json` 里的索引根是源机器的路径（形如 `~/Documents/…`）。拷过去要手改，否则下次 `index` 会告诉你「索引根不存在」。
- `claims.db` 是**判断/签字记录**（谁、什么时候、认还是不认），它和索引不是一类东西：索引可重建，**判断不可重建**。要不要一起带走，由你自己决定。

## 二、装 App

1. 打开 `本地上下文-<版本>.dmg`（本轮是 `本地上下文-1.1.0.dmg`；版本号来自 `mcp-server/package.json`，App 与 CLI 同源）。
2. 把 `本地上下文.app` 拖进右边的 `Applications` 软链（那就是 `/Applications`）。
3. **不要指望第一次双击能打开** —— 见下一节。

dmg 里还放了一份这份说明的副本，装的时候就能看。

## 三、Gatekeeper：两条真实可行的放行办法

**为什么会被拦 —— 先看这台机器上的原始判定**（不是"听说"）：

Apple 自带一个 `syspolicy_check`，它自己的说明是：「跑的就是 macOS 决定一个 app 能不能被执行时的同一套检查（含 Gatekeeper、XProtect、描述文件）」。在一份**加了隔离属性的副本**上跑（模拟"从网上下载来的 App"；副本放在 `/tmp`，没有碰 `dist/`）：

```sh
$ xattr -w com.apple.quarantine "0081;202610022024;Safari;" /tmp/gk-test/本地上下文.app
$ syspolicy_check distribution /tmp/gk-test/本地上下文.app
# stderr:
App has failed one or more pre-distribution checks.
# stdout:
Adhoc Signed App
    Severity: Warning
    Full Error: This app is adhoc signed. While it may run locally, adhoc
        signed apps are not suitable for distribution.
    Type: Distribution Error
    Suggested Fix: Sign the app with a valid Developer ID certificate for distribution.
Notary Ticket Missing
    Severity: Fatal
    Full Error: A Notarization ticket is not stapled to this application.
    Type: Distribution Error
    Suggested Fix: … upload to the Apple notary service using Xcode or via `notarytool`.
（exit 70）

$ spctl -a -vvvv --type execute /tmp/gk-test/本地上下文.app
/tmp/gk-test/本地上下文.app: rejected
（exit 3）
```

两条判定正好对上：**Fatal 的那一条是「没有公证票」** —— 这就是别的 Mac 上第一次打开被拦的直接原因；Warning 的那一条说明为什么会没有票：adhoc 签名**不可用于分发**。

从 dmg 拷进 `/Applications` 的 App 同样会带隔离属性，先用这条命令看它有没有：

```sh
xattr -l /Applications/本地上下文.app
```

### 办法 A：GUI 放行（不需要终端）

1. 先在 Finder 里**试着打开一次**这个 App —— 会被拦下来，出现「无法验证开发者」之类的提示，关掉它。
2. 打开 **系统设置 → 隐私与安全性**，拉到底部，在「安全性」区域会出现一条关于这个 App 的提示和一个 **「仍要打开」** 按钮。
3. 点「仍要打开」，系统还会再确认一次；确认后 App 就能打开了。

> **在 macOS 14 及更早的版本上**，等价操作是：Finder 里 **按住 Control 点（或右键）图标 → 「打开」→ 弹窗里再点一次「打开」**。
> **macOS 15 起 Apple 去掉了右键这条后门**，只能走「系统设置 → 隐私与安全性 → 仍要打开」。
> 本机是 macOS 26.6，按上面三步走；这是 Apple 的机制变更，见
> <https://support.apple.com/zh-cn/102445>（未在第二台机器上实机复现，见第六节）。

### 办法 B：终端一条命令去掉隔离属性（等价，可脚本化）

```sh
xattr -d com.apple.quarantine /Applications/本地上下文.app
```

- 如果报 `No such xattr`，说明隔离属性本来就没有（例如用 `ditto` 拷贝、或已经放行过）——不用再执行。
- 如果提示「已损坏，无法打开」，先确认你拿到的 dmg 的 SHA-256 和发布处一致，再执行这一条。
  `xattr -cr` 会递归清掉所有扩展属性，一般**不需要**，也不建议。
- 做完以后（隔离属性已经清掉了）直接双击就能打开。

> **为什么这两条有用**：Gatekeeper 拦的是「未公证 + 带隔离属性」这个组合。清掉隔离属性后，系统在这一步只校验签名完整性 —— 而这个包的 adhoc 签名是**自洽**的（实测 `codesign --verify --deep --strict` → `valid on disk` / `satisfies its Designated Requirement`）。
>
> **为什么不能一劳永逸**：要免放行必须走完整条分发链路 —— Apple Developer ID 证书 → `codesign --deep --sign "Developer ID Application: …"` → `xcrun notarytool submit` 公证 → `xcrun stapler staple` 装订。**本机 0 张证书**，这一整条现在做不了。

## 四、放行之后

```sh
# 自检（无头，不进界面）
/Applications/本地上下文.app/Contents/MacOS/LocalVault --selftest

# 设置签字人（judgment 的 signed_by 不允许为空，所以必须有办法设）
/Applications/本地上下文.app/Contents/MacOS/LocalVault --signer "你的名字"

# 直接带着检索词进「检索库」
/Applications/本地上下文.app/Contents/MacOS/LocalVault --tab 检索库 --query "项目"
```

打开 App 如果看到「还没有可读的索引」，说明第一节没做。按它给的命令做完，**重启 App**
（App 只在启动时读一次索引，没有自动重试；而且没有索引时连工具栏都不会出现，只能重启）。
已经打开的界面里，工具栏右侧有一个 **「重读索引」**（⌘R）—— 那只是重新读一遍索引库，不扫描磁盘、不改动任何文件。

## 五、数据落在哪

| 路径 | 是什么 | 能不能删 |
|---|---|---|
| `~/.localvault/vault.db` | 索引本体（约 90 MB 量级，随索引范围变） | 能。重跑 `index` 就重建 |
| `~/.localvault/config.json` | 索引哪些根、忽略哪些目录、脱敏名单 | **别手删**，删了要重跑 `init` |
| `~/.localvault/claims.db` | 判断/条陈（人签的字，只增不改） | **不能删**，它不可重建 |
| `~/.localvault/index.log` | 索引日志 | 能 |

- App **只读**：`vault.db` 以 `?mode=ro` 打开，界面上不接受任何会改文件的动作。
- `--selftest` 与 `--signer` 会打开 `~/.localvault/claims.db`（启动时 `CREATE TABLE IF NOT EXISTS`），
  所以它们**不是完全无副作用**；只是都不碰你的文件。
- Linux / Windows **没有**图形版：App 是 SwiftUI、macOS 14+ 专用。CLI 是 Node，跨平台。

## 六、这份文档没验证的部分（别当成事实）

1. **没有在第二台干净的 Mac 上实机走一遍。** 手边没有第二台机器。
   **"会被拦"这件事本身是本机实测的**（第三节的 `syspolicy_check` / `spctl` 原始输出，
   跑在一份加了隔离属性的副本上）；**没验的是"放行之后长什么样"** ——
   也就是在别的机器上点「仍要打开」的实际交互。第一次照这个做的时候，
   如果步骤和这里不一样，以系统实际提示为准，并回来改这份文档。
2. **macOS 15+ 改用「系统设置 → 仍要打开」**这一条：机制说明，未实机复现
   （本机的隔离属性副本只在命令行上过了一遍判定，没有真的点开它 ——
   不敢在你这台正在用的机器上真的去启动一个未签名 App 让 LaunchServices 记一笔）。
3. **npm 的发布状态**是 2026-10-02 的实测（上面三条 curl 的输出）。包一旦发布就过期。
4. `--selftest` 的具体项数没有在本轮复跑（它会打开真实的 `claims.db`）；
   最近一次记录是任务背景里的 **127/127**，由 Lead 侧实跑。

## 附：本机的签名实况（可复现）

```sh
$ codesign -dvv dist/本地上下文.app 2>&1 | grep -E 'Signature|TeamIdentifier|Format'
Format=app bundle with Mach-O thin (arm64)
Signature=adhoc
TeamIdentifier=not set

$ security find-identity -v -p codesigning
     0 valid identities found

$ spctl -a -vvv --type execute dist/本地上下文.app
dist/本地上下文.app: rejected

$ xcrun stapler validate dist/本地上下文.app
本地上下文.app does not have a ticket stapled to it.

$ codesign --verify --deep --strict --verbose=2 dist/本地上下文.app
dist/本地上下文.app: valid on disk
dist/本地上下文.app: satisfies its Designated Requirement

$ syspolicy_check distribution /tmp/gk-test/本地上下文.app     # 加过隔离属性的副本
App has failed one or more pre-distribution checks.            # exit 70
# 详见第三节：Adhoc Signed App（Warning）+ Notary Ticket Missing（Fatal）

$ spctl -a -vvvv --type execute /tmp/gk-test/本地上下文.app
/tmp/gk-test/本地上下文.app: rejected                           # exit 3
```

最后两条合起来才是完整的意思：**本机自洽（所以能放行），但对别的机器不可信（所以会被拦）。**
